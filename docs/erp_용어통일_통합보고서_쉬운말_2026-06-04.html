3. 누가 뭘 하나 시스템별 작업 누가 맡나

시스템난이도담당예상 기간무슨 작업
상품DB (시트) 쉬움 박차장 + 어시스턴트 1~2주 구글 시트에 자동 갱신 스크립트 한 번 박아두면 끝. 1,061건이 알아서 정리됨
ERP 보통 개발팀 2~3주 ERP에 "이름 바꿔줘" 받을 창구 1개만 만들면 됨. 코드는 그대로 두고 표시 이름만 바뀜

전부 합쳐 3~6주, 외주비 0원. 개발팀이 ERP·챗봇 둘 다 관리해서 외부 협의 필요 없습니다.

5. 절대 지켜야 할 6가지

원칙왜 이게 중요한가
① ERP 코드는 절대 바꾸지 않기 준드(104)·UV출력기(다른 ID) 이 코드를 바꾸면 옛 주문·매출·재고가 다 깨집니다. 화면 이름만 바꾸고 코드는 그대로 둠.
② 옛 이름 ↔ 새 이름 ↔ 고객말 모두 보관 옛 자료 검색 + 챗봇에서 고객이 "포멕스 있나요?" 물을 때도 매칭되어야 함. 모든 표현을 사전에 묶어두기.
③ 챗봇은 동의어 사전 방식 "포맥스 = 포맥스3T = 포멕스 = 폼보드" 묶음. 어떤 표현으로 와도 같은 답.
④ 5명 동의된 항목만 자동 반영 회의에서 협의 중인 임시값이 ERP나 챗봇에 잘못 들어가면 사고. 5명 동의(전체동의) 체크된 것만 자동 전달.
⑤ 변경 이력 영원히 보존 "왜 이 이름으로 정했지?" 6개월 뒤·1년 뒤도 추적 가능해야 함. 누가 언제 무엇을 했는지 다 기록.
⑥ 되돌리기(UNDO) 항상 가능 실수로 잘못 박았을 때 한 번에 원상복구. 잘못된 변경이 시스템에 박혀버리는 사고 방지.

6. 조심해야 할 5가지

위험발생 가능성피해 크기막는 방법
ERP 코드 실수로 바꿈 → 과거 이력 깨짐 중간 치명적 회의 도구에서 코드 칸은 읽기전용. 개발팀 창구에서도 코드 변경 거부
자동 반영 지연·실패 → ERP/챗봇 표시 불일치 중간 중간 자동 재시도 3회 + 실패 로그·알림. 매일 1회 정합성 확인 자동 실행
회의에서 잘못된 결정 박힘 → 시스템에 반영 낮음 중간 5명 동의 가드 + 되돌리기 20회. 추가로 24시간 지연 옵션 가능
회의 도구 외부 무단 변경 중간 치명적 회의 끝나면 비밀번호로 접근 제한. 지금은 임시로 풀어두었으니, 통일 작업 끝나면 잠가야 함
개발팀 일정 지연 중간 중간 0단계(손 작업)로 그대로 운영 가능. 1단계(상품DB)부터 외주 0으로 자체 진행

7. 회의 도구에 칸 두 개만 더 추가 권장

지금 회의 도구에 두 칸만 더 박으면, 나중에 자동화 작업이 며칠 빨라집니다.

추가할 칸왜 이게 필요한가예시
ERP 코드 번호 ERP가 내부적으로 쓰는 번호. 이 번호를 알아야 "이 코드의 이름만 바꿔줘" 자동 요청 가능. 코드 자체는 절대 안 바꿈. 1 (포맥스3T) · 104 (스텐304)
옛이름·고객표현 모음 챗봇이 어떤 표현으로 와도 매칭하려면 다 알고 있어야 함. "포맥스 / 포맥스 3T / 포멕스 / 폼보드 / 5T 보드"
회의 중에 이 두 칸 채우면 시간 30분 정도 더 듭니다. 대신 자동화 시작 시 며칠 분량의 데이터 정리를 절약합니다.

8. 결정해야 할 것들

지금 (이번 미팅 또는 내일까지)

  • 회의 도구에 ERP 코드 번호·옛이름 모음 칸 추가할지 (15분 작업)
  • 1단계(상품DB 자동) 지금 바로 시작할지, 회의 다 끝나고 시작할지
  • 회의 일정 잡기 — 5명 모이는 첫 회의 언제

1~2주 안에

  • 개발팀과 2단계 협의 미팅 잡기 (ERP·챗봇 자동 반영)
  • ERP의 자재·공정·장비 코드 구조 받기
  • 챗봇 외주사 → 개발팀 이관 일정 확인

1개월 안에

  • 대표 보고 — 이 문서로 "한 곳에서 관리하는 통일 기준" 정책 승인 받기
  • 2단계 시작·담당자 확정
  • 통일 진행률 대시보드 만들지 결정
